# AI Agent API

FastAPI backend for user authentication, chat creation, PDF upload, document extraction, RAG indexing, and agent chat over uploaded documents. The app uses PostgreSQL for metadata, Redis/Celery for background processing, Qdrant for vector search, Ollama for LLM/embedding/vision models, and LangGraph checkpointing.

## Main Services

| Service | Purpose |
| --- | --- |
| `web-api` | FastAPI HTTP API for users, chats, files, agent chat, tasks, and health checks. |
| `worker` | Celery worker that processes uploaded PDFs through extraction, vision enrichment, grouping, summarization, and vector indexing. |
| `postgres` | Stores users, chats, files, and file-processing stages. |
| `redis` | Celery broker/result backend and file-summary cache. |
| `qdrant` | Vector database for RAG retrieval. |
| `ollama` | Local model server for text, embedding, and vision models. |
| `docling-viewer` | Streamlit viewer for extracted Docling/RAG artifacts. |

## Requirements

- Python 3.12
- Docker and Docker Compose, recommended for dependencies
- PostgreSQL, Redis, Qdrant, and Ollama if running without Docker
- NVIDIA GPU support is expected by the current Docker Compose configuration for Ollama and the worker

## Environment Variables

Create a `.env` file in the project root. The application reads these variables through `core/settings.py`.

```env
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DB=aiagent

DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5433/aiagent
JWT_SECRET=replace-with-a-long-random-secret
JWT_EXPIRES_SECONDS=3600

REDIS_URL=redis://localhost:6379/0
QDRANT_URL=http://localhost:6333
RAG_COLLECTION_NAME=rag_chunks

EMBEDDING_MODEL=qwen3-embedding
OLLAMA_URL=http://localhost:11434
TEXT_MODEL=llama3.1:8b
VISION_MODEL=llama3.2-vision:11b

LANGSMITH_TRACING=false
LANGSMITH_ENDPOINT=https://api.smith.langchain.com
LANGSMITH_API_KEY=
LANGSMITH_PROJECT=ai-agent
LANGGRAPH_CHECKPOINT_DB_URL=postgresql://postgres:postgres@localhost:5433/aiagent

```

For Docker Compose, service hostnames are internal container names. Example:

```env

REDIS_URL=redis://redis:6379/0

```

## Setup With Docker Compose

1. Create `.env`.
2. Start infrastructure and services:

```bash
docker compose up -d --build
```

3. Run database migrations:

```bash
docker compose exec web-api alembic upgrade head
```

4. Open API docs:

```text
http://localhost:8080/docs
```

5. Open health check:

```text
http://localhost:8080/health
```

6. Optional: open the Docling/RAG viewer:

```text
http://localhost:8501
```

## Local Development Setup

1. Create and activate a virtual environment:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
```

2. Install dependencies:

```bash
pip install -r requirements.txt
pip install -r requirements-dev.txt
```

3. Start required services with Docker, or provide your own PostgreSQL, Redis, Qdrant, and Ollama instances:

```bash
docker compose up -d postgres redis qdrant ollama
```

4. Run migrations:

```bash
alembic upgrade head
```

5. Start the API:

```bash
uvicorn main:app --host 0.0.0.0 --port 8080 --reload
```

6. Start the Celery worker in a second terminal:

```bash
celery -A worker.celery_app worker --loglevel=INFO
```

7. Optional: start the artifact viewer:

```bash
streamlit run tools/docling_viewer.py --server.address=0.0.0.0 --server.port=8501
```

## Authentication Flow

Most endpoints require a Bearer token.

1. Register a user with `POST /users/register`.
2. Login with `POST /users/login`.
3. Use the returned `access_token` in protected requests:

```http
Authorization: Bearer <access_token>
```

### Files Service

#### `POST /files/upload`

Uploads one or more PDF files for a chat. The API stores file metadata and queues background extraction/indexing work through Celery.

Authentication: required.

Content type: `multipart/form-data`

Form fields:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `chat_id` | string | yes | Chat UUID returned by `POST /chats`. |
| `files` | file[] | yes | One or more PDF files. |

Response `201`:

```json
{
  "user_id": 1,
  "chat_id": "8bb6bda8-b84f-4908-8a2c-06d3e016726c",
  "files": [
    {
      "file_id": "f4f2919c-77fb-4a23-bab1-cd4b95c7b7ca",
      "chat_id": "8bb6bda8-b84f-4908-8a2c-06d3e016726c",
      "file_name": "document.pdf",
      "unique_generated_name": "19f3f617-4d15-4328-ad1a-8f2aa9d7f450.pdf",
      "full_path": "/abs/path/uploads/1/19f3f617-4d15-4328-ad1a-8f2aa9d7f450.pdf"
    }
  ]
}
```

Example:

```bash
curl -X POST http://localhost:8080/files/upload \
  -H "Authorization: Bearer <access_token>" \
  -F "chat_id=8bb6bda8-b84f-4908-8a2c-06d3e016726c" \
  -F "files=@/path/to/document.pdf;type=application/pdf"
```

### Agent Service

#### `POST /agent/chat`

Runs the RAG agent for a chat and prompt. The agent retrieves indexed chunks from Qdrant and generates an answer using Ollama/LangGraph.

Authentication: required.

Request body:

```json
{
  "chat_id": "8bb6bda8-b84f-4908-8a2c-06d3e016726c",
  "prompt": "Summarize the uploaded document"
}
```

`query` is also accepted as an alias for `prompt`.

Response `200`:

```json
{
  "chat_id": "8bb6bda8-b84f-4908-8a2c-06d3e016726c",
  "prompt": "Summarize the uploaded document",
  "answer": "The document explains...",
  "parsed_query": null,
  "retrieved_chunks": [],
  "context": "..."
}
```

Example:

```bash
curl -X POST http://localhost:8080/agent/chat \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"chat_id":"8bb6bda8-b84f-4908-8a2c-06d3e016726c","prompt":"Summarize the uploaded document"}'
```

#### `POST /agent/chat/stream`

Streams the RAG agent answer as Server-Sent Events.

Authentication: required.

Request body:

```json
{
  "chat_id": "8bb6bda8-b84f-4908-8a2c-06d3e016726c",
  "prompt": "Summarize the uploaded document"
}
```

Response content type:

```text
text/event-stream
```

SSE events include:

| Event | Meaning |
| --- | --- |
| `debug` | Internal progress message. |
| `start` | Stream started. |
| `token` | Incremental generated text. |
| `done` | Stream completed. |
| `error` | Stream failed. |

Example:

```bash
curl -N -X POST http://localhost:8080/agent/chat/stream \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{"chat_id":"8bb6bda8-b84f-4908-8a2c-06d3e016726c","prompt":"Summarize the uploaded document"}'
```

### Tasks Service

Authentication: not currently enforced in the controller.

Query parameters:

| Parameter | Type | Required | Description |

| `task_name` | string | no | Exact Celery task name. |

Response `200`:

```json
{
  "total": 1,
  "filters": {
    "status_filter": ["SUCCESS"],
    "task_name": null
  },
  "tasks": [
    {
      "task_id": "abc123",
      "task_name": "process_uploaded_file",
      "status": "SUCCESS",
      "result": null,
      "traceback": null,
      "date_done": "2026-06-02T10:00:00",
      "worker": null,
      "args": null,
      "kwargs": null,
      "eta": null
    }
  ]
}
```

Examples:

```bash
curl "http://localhost:8080/tasks"
curl "http://localhost:8080/tasks?status_filter=SUCCESS,FAILURE"
curl "http://localhost:8080/tasks?task_name=process_uploaded_file"
```

#### `GET /tasks/{task_id}`

Returns the status/result for a Celery task.

Authentication: not currently enforced in the controller.

Response example:

```json

  "task_id": "abc123",
  "status": "SUCCESS",
  "result": null
```

#### `POST /tasks/{task_id}/retry`

Retries a Celery task. If the original task name cannot be inferred, pass `task_name` in the request body.

Authentication: not currently enforced in the controller.

Request body:

```json
{
  "task_name": "process_uploaded_file",
  "args": [],
  "kwargs": {},
  "countdown": 0

```

Response `200`:

```json
{
  "source_task_id": "abc123",
  "retried_task_id": "new-task-id",
  "task_name": "process_uploaded_file",
  "args": [],
  "kwargs": {},
  "countdown": 0
}
```

Example:

```bash
curl -X POST http://localhost:8080/tasks/abc123/retry \
  -H "Content-Type: application/json" \
  -d '{"task_name":"process_uploaded_file","args":[],"kwargs":{},"countdown":0}'
```

## Background File Processing Pipeline

When PDFs are uploaded, the Celery task `process_uploaded_file` runs these stages:

1. Extract PDF structure/assets with Docling.
2. Add image/table vision analysis.
3. Group markdown by main headings.
4. Build section summaries.
5. Build and save vector embeddings to Qdrant.
6. Update per-stage status in the database.

Generated artifacts are stored under ignored local directories such as `uploads/` and `extracted_files/`.

## Troubleshooting

### `401 Invalid or expired token`

Login again and use the latest access token in the `Authorization` header.

### Uploaded files do not appear in RAG answers

Check worker and task status:

```bash
docker compose logs -f worker
curl http://localhost:8080/tasks
```

Confirm Qdrant and Ollama are reachable:

```bash
curl http://localhost:6333/healthz
curl http://localhost:11434/api/tags
```

### Migrations fail to connect

Verify `DATABASE_URL` and `LANGGRAPH_CHECKPOINT_DB_URL` match your runtime mode. Docker uses service names like `postgres`; local runs usually use `localhost` and exposed ports.
